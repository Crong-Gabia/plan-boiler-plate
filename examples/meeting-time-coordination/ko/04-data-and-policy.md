# 04. 데이터/프라이버시 정책 초안

상태: `DRAFT_FLOW`

작성일: 2026-01-30

## 1) 데이터 인벤토리(최소 수집 원칙)

### 1.1 사내 사용자(Organizer/Participant)

- 식별: 사내 계정 ID, 표시명, 이메일(또는 사번)
- 폴 데이터: 폴 제목/설명, 슬롯, 응답
- 운영 데이터: 생성/수정/확정/삭제 이벤트, 접근 로그(보안 목적)

### 1.2 외부 게스트(Guest Participant)

- 식별: 이메일(초대/확인 목적) + 표시명(선택)
- 접근: 투표 링크 토큰(만료 가능)
- 응답: 슬롯별 가용성

## 2) 권한/경계 모델

- 데이터 소유권은 기본적으로 “조직(테넌트)”에 귀속된다.
- 외부 게스트는 “참여자”일 뿐이며, 조직 리소스(사내 디렉토리/다른 폴 등)에 접근할 수 없다.

## 3) 보관/삭제 정책(제안)

- 확정된 폴: 확정 후 90일 자동 삭제(기본)
- 미확정 폴: 생성 후 30일 자동 삭제(기본)
- 토큰/접근 로그: 보안 목적 최소 기간 보관(예: 30~90일) 후 집계/익명화

> 삭제 의미: 사용자 화면에서의 삭제(즉시 비노출)와 백업/감사 메타데이터 잔존 여부를 분리해 명시한다.

## 4) 서브프로세서/외부 연동(초안)

- v1 기준: (미정) 이메일 발송, 파일/백업 저장, 모니터링 등에서 외부 서비스가 사용될 수 있음
- 정책 문서에 아래를 최소 포함해야 함:
  - 목록(서비스명)
  - 목적(메일 발송/호스팅/모니터링 등)
  - 데이터 범주(어떤 개인정보/콘텐츠가 전달되는지)
  - 리전/이전(국외 이전 여부)
  - 변경 고지(업데이트 시 알림 방식)

## 5) 관리자 제어(Admin controls)

- 외부 게스트 허용 on/off
- 기본 보관 기간(TTL) 설정 및 최대/최소 제한
- 데이터 내보내기(감사/분쟁 대응)
- 삭제 요청 처리(사용자/게스트 요청)
