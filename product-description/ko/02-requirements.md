# 02. 요구사항 (Functional / Non-functional)

상태: `DRAFT_FLOW`

작성일: 2026-01-30

## 1) 기능 요구사항 (v1)

### 1.1 폴(Poll) 생성

- Organizer는 폴 제목/설명, 기본 타임존, 후보 슬롯(날짜/시간 구간)을 입력할 수 있어야 한다.
- 후보 슬롯은:
  - 최소: 날짜+시작/종료
  - 권장: 반복 입력(예: 매일 14:00~17:00) 보조
- 폴은 공유 가능한 URL(투표 링크)과 관리자 URL/화면(관리 대시보드)을 가진다.

### 1.2 초대(Invites)

- 사내 참석자 초대:
  - 이메일/사내 디렉토리 검색으로 추가
  - 로그인 후 응답
- 외부 게스트 초대:
  - 이메일 주소로 초대 발송
  - 토큰 기반 투표 링크로 응답
  - (옵션) 이메일 매직링크/1회성 코드로 본인 확인

### 1.3 응답(Voting)

- 참석자는 각 슬롯에 대해 최소 3-state로 응답할 수 있어야 한다.
  - 예: 가능 / 불가 / 조건부(가능하면)
- 참석자는 자신의 타임존으로 변환된 시간을 볼 수 있어야 한다.
- Organizer는 전체 응답 현황(집계)을 볼 수 있어야 한다.

### 1.4 확정(Decision)

- Organizer는 슬롯 중 하나를 확정할 수 있어야 한다.
- 확정 시:
  - 참석자에게 알림(이메일/사내 메신저 연동은 옵션)
  - 확정 결과 페이지(읽기 전용) 제공

### 1.5 캘린더 반영 (범위 TBD)

- 최소(v1 후보):
  - 확정 후 `.ics` 다운로드 제공
- 확장(v1.5/v2 후보):
  - 사내 사용자 캘린더 연결(읽기: busy time 조회)
  - 확정 시 자동 이벤트 생성/업데이트(쓰기)

### 1.6 내보내기/기록

- Organizer는 응답 결과를 CSV로 내보낼 수 있어야 한다.
- (조직형) Admin은 감사 로그(Audit log)를 조회할 수 있어야 한다.

## 2) 권한/보안 요구사항

### 2.1 인증

- 사내 사용자: 조직 계정으로 인증(SSO 등) (구체 구현은 추후 결정)
- 외부 게스트: 링크(토큰) 기반 접근

### 2.2 권한 경계

- Organizer 대시보드는 반드시 인증된 Organizer만 접근 가능해야 한다.
- 투표 링크는 기본적으로 “링크를 가진 자” 접근이 가능하므로, 다음 중 최소 1개 이상을 제공한다.
  - 토큰 만료(기본 TTL)
  - 링크 재발급(기존 링크 폐기)
  - (옵션) 초대 이메일과 매칭되는 사용자만 투표 허용

### 2.3 노출 최소화

- 참석자에게 다른 참석자의 이메일/조직 정보를 과도하게 노출하지 않는다.
  - 외부 게스트가 포함된 경우, 기본값은 **표시명 최소화/익명 옵션**을 고려한다.

## 3) 데이터/보관(초안)

### 3.1 데이터 최소 수집

- 필수: 폴/슬롯/응답, 내부 사용자 식별자, 게스트 이메일(초대/확인 목적)
- 선택: 메모, 조건부 가능 사유

### 3.2 보관 기간(제안)

- 확정된 폴: 확정 후 90일 자동 삭제(기본값)
- 미확정 폴: 생성 후 30일 자동 만료/삭제(기본값)
- Admin은 테넌트 정책으로 최대 보관 기간/최소 보관 기간을 제한할 수 있다.

## 4) 비기능 요구사항

- 타임존: IANA timezone 기반(예: `Asia/Seoul`)으로 일관 처리
- 가용성/성능: 일반적인 사내 사용(수십~수백명)에서 투표 페이지 로딩/응답 저장이 병목 없이 동작
- 접근성: 키보드/스크린리더 최소 요건 충족
- 로깅: 보안 이벤트(토큰 재발급, 대량 접근 시도 등) 기록
- 국제화: 한국어 우선, 영어는 미러 문서/추후 UI 확장 가능
